What We Do

Embedded

요구 사항을 정리하는 일에서 양산 검증까지 여섯 단계로 진행합니다. 하드웨어의 한계와 안전·보안 요구를 설계 단계부터 반영합니다.

01

요구 분석 · 시스템 설계

기능·안전 요구와 하드웨어 제약을 설계·검증 기준으로 확정해 양산 단계의 재작업을 줄입니다.

  • 요구 분리 기능 요구와 안전 요구(HARA·ASIL)를 나눠 추적 가능한 형태로 정의
  • 제약 반영 설계 메모리·전력·발열을 반영한 SW 아키텍처와 단계별 검증 계획
  • 표준 적용 판단 AUTOSAR Classic/Adaptive 적용 여부를 프로젝트 특성에 맞춰 결정
02

보드 초기 구동 · 운영체제 기반(BSP) 적용

타깃 보드에서 부트로더·커널·드라이버를 구동하고, 재현 가능한 보드 지원 패키지(BSP) 빌드 환경을 확보합니다.

  • 보드 포팅 부트로더·커널·드라이버를 타깃 보드에 올리고 주변장치 하나씩 검증
  • 재현 가능한 빌드 Yocto 기반 보드 지원 패키지(BSP) 구성 — 누가 빌드해도 같은 결과
  • 초기 지표 부팅 시간·메모리 사용량을 재어 양산 목표치 조기 설정
03

운영체제 · 플랫폼 구성

실시간성·앱 생태계·업데이트 요구에 맞춰 OS와 격리·복구 구조를 구성합니다.

  • OS 선택 실시간 영역은 QNX·RTOS, 앱 생태계가 필요한 영역은 Linux·차량용 Android(AAOS)
  • 도메인 분리 컨테이너·하이퍼바이저로 안전 기능과 인포테인먼트 격리
  • OTA 전제 A/B 파티션과 실패 시 자동 복구 체계
04

차량 화면(HMI) · 미들웨어 개발

차량 화면과 센서·서비스 통신을 함께 개발해 일관된 사용자 경험과 안정적인 데이터 흐름을 구현합니다.

  • 차량 화면(HMI) Qt·QML 기반 화면을 프레임 저하 최소화 기준으로 개발
  • 차량 네트워크 차량 서비스 통신(SOME/IP)·제어망(CAN)·차량 이더넷 미들웨어 개발·통합
  • 도메인 앱 내비게이션·미디어·공조 등 서비스 계층 구현
05

통합 검증 · 기능안전

가상 장비 시험(HIL)·실차·정적분석으로 요구사항과 기능안전·보안을 검증하고, 회귀 결함을 조기에 발견해 재발 위험을 낮춥니다.

  • 커버리지 검증 가상 장비 연동 시험(HIL)과 실차 테스트로 요구사항 확인
  • 표준 프로세스 ISO 26262 기능안전 · ISO 21434 사이버보안(TARA)
  • 회귀 차단 MISRA C 정적분석·단위·통합 테스트를 CI에 연결
06

최적화 · 양산 대응

부팅·응답·메모리를 목표치에 맞추고 플래싱·검사·업데이트 체계를 양산 라인에 연결합니다.

  • 목표 스펙 최적화 부팅 시간·응답 지연·메모리 프로파일링
  • 양산 라인 대응 플래싱·검사 체계와 UDS 진단 프로토콜 지원
  • 규정·유지보수 UN R156 SW 업데이트 대응과 양산 이후 체계 구축
